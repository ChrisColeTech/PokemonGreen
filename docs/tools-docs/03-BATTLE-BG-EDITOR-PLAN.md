# 03 - Battle Background Editor Plan

## Goal

A web tool for loading 3D battle background models (.dae, .obj, .fbx), previewing them with textures in a live 3D viewport, adjusting texture colors (hue, saturation, brightness, tint), and exporting modified textures as PNGs for the game engine.

Located at `src/PokemonGreen.BgEditor/`.

---

## Architecture

### Frontend (React + Vite + Three.js)

Handles rendering, UI, and texture manipulation. Communicates with the backend to browse and load models.

### Backend (Express)

A lightweight local API server that reads model and texture files from disk and serves them to the frontend. This is necessary because browsers cannot read local files by path — all file access goes through the backend.

---

## Asset Structure

Models and textures live in `Assets/` with this structure:

```text
Assets/
  BattleBG/
    Grass/
      Grass.dae
      batt_field01.png
      batt_sky01.png
      manifest.json
    Cave/
      Cave.dae
      batt_field05.png
      batt_sky05.png
      manifest.json
    ...
  Pokemon/
    pm0001_00_Rig/
      pm0001_00_Rig.fbx
      pm0001_00_BodyAll1.png
      pm0001_00_Eye1.png
      manifest.json
    ...
```

Each folder containing a model has a `manifest.json` generated by the manifest generator script. The manifest lists the model file, its format, and texture filenames:

```json
{
  "name": "pm0001_00_Rig",
  "modelFile": "pm0001_00_Rig.fbx",
  "modelFormat": "fbx",
  "textures": [
    "pm0001_00_BodyAll1.png",
    "pm0001_00_Eye1.png"
  ]
}
```

For OBJ models with an MTL file:

```json
{
  "name": "SomeModel",
  "modelFile": "model.obj",
  "modelFormat": "obj",
  "textures": ["diffuse.png", "normal.png"],
  "mtlFile": "model.mtl"
}
```

---

## Manifest Generator

**Script:** `scripts/generate-manifests.ts`
**Run with:** `npm run generate-manifests`

Scans `Assets/` recursively. For each folder containing a model file (.fbx, .dae, .obj), writes a `manifest.json` listing the model, format, texture filenames, and optional MTL file. The manifests are lightweight metadata only — no file contents are embedded.

## Backend API

**Location:** `server/` directory within the BgEditor project.
**Tech:** Express + TypeScript, run with tsx.
**Start with:** `npm run dev` (runs both Vite frontend and Express backend concurrently).

### Endpoints

#### `GET /api/manifests`

Scans the Assets directory for all `manifest.json` files and returns a list of available models.

**Response:**
```json
[
  {
    "name": "pm0001_00_Rig",
    "modelFile": "pm0001_00_Rig.fbx",
    "modelFormat": "fbx",
    "textures": ["pm0001_00_BodyAll1.png", "pm0001_00_Eye1.png"],
    "path": "Pokemon/pm0001_00_Rig"
  },
  {
    "name": "Grass",
    "modelFile": "Grass.dae",
    "modelFormat": "dae",
    "textures": ["batt_field01.png", "batt_sky01.png"],
    "path": "BattleBG/Grass"
  }
]
```

The `path` field is relative to the Assets root, used to request individual files.

#### `GET /api/file/:path`

Reads and returns a file from the Assets directory. The path is relative to the Assets root.

**Examples:**
- `GET /api/file/Pokemon/pm0001_00_Rig/pm0001_00_Rig.fbx` — returns the FBX binary
- `GET /api/file/Pokemon/pm0001_00_Rig/pm0001_00_BodyAll1.png` — returns the PNG image
- `GET /api/file/BattleBG/Grass/Grass.dae` — returns the DAE XML

Sets appropriate Content-Type headers based on file extension. Returns 404 if the file doesn't exist. Must validate the path stays within the Assets directory (no path traversal).

## Frontend

### Loading Flow

1. On startup, frontend calls `GET /api/manifests` to get the list of available models.
2. User browses/searches the model list and selects one.
3. Frontend fetches the model file from `GET /api/file/{path}/{modelFile}`.
4. Frontend fetches each texture from `GET /api/file/{path}/{textureName}`.
5. If OBJ with MTL, frontend also fetches the MTL file.
6. Frontend parses the model with Three.js (FBXLoader/ColladaLoader/OBJLoader).
7. Frontend creates textures from the fetched images and assigns them to materials.
8. Scene renders in the 3D viewport with textures visible.

### Scene Service Changes

`sceneService.ts` is updated to:
- Accept fetched ArrayBuffer (model) and loaded Image elements (textures) instead of user-selected Files.
- Parse model geometry using the appropriate Three.js loader.
- Walk the scene's materials and assign the fetched texture images to material map slots, matching by filename.
- No longer relies on Three.js's internal texture loading (which constructs invalid localhost URLs).

### UI Changes

- **DropZone** is replaced with a **ModelBrowser** component that shows available models from the API.
- **InfoBar** "Load Manifest" button is replaced with model selection from the browser list.
- **editorStore** `loadManifest` action takes a manifest object (from the API) instead of a File, fetches the model and textures from the backend, and loads the scene.

## Color Controls

Per-texture adjustment sliders:

| Control | Range | Default |
|---------|-------|---------|
| Hue Shift | -180 to +180 | 0 |
| Saturation | -100 to +100 | 0 |
| Brightness | -100 to +100 | 0 |
| Tint Color | Color picker | none |
| Tint Strength | 0 to 100 | 0 |

Changes apply in real-time to the 3D preview. "Apply to All" applies adjustments to every texture. "Reset" reverts to original.

---

## Export

- Modified PNGs exported via canvas `toBlob()`.
- Packaged as a zip with the original folder structure for dropping into `Assets/`.
- Uses JSZip for packaging.

---

## Implementation Order

1. **Manifest generator** — generate lightweight manifest.json files in Assets folders.
2. **Backend server** — Express API to list manifests and serve files.
3. **API service** — frontend module to call backend endpoints.
4. **Model browser UI** — replace DropZone with model list from API.
5. **Scene loading via API** — fetch model + textures from backend, parse and render.
6. **Verify textures load** — confirm models display with correct textures in viewport.
7. **Color adjustment** — already partially built (ColorControls, TexturePanel exist).
8. **Export** — zip packaging of modified textures.
